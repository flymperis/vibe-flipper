# Vibe Flipper

Παρακολουθεί αγγελίες μεταχειρισμένων προϊόντων τεχνολογίας/gaming από **Insomnia.gr**, **Vendora.gr** και **Vinted**, τις αντιστοιχίζει σε προϊόντα, κρατά ιστορικό τιμών και δείχνει για κάθε νέα αγγελία το περιθώριο κέρδους σε σχέση με την αγοραία (διάμεση) τιμή.

## Εκκίνηση (Docker / Podman)

```bash
cp .env.example .env        # βάλε OLLAMA_URL αν θες LLM matching
podman-compose up -d --build   # ή: docker compose up -d --build
```

Άνοιξε `http://<server>:8000`. Στην πρώτη εκκίνηση φορτώνονται τα προϊόντα από το `seed_products.yaml` και γίνεται ένα πιο βαθύ scrape (backfill). Μετά τρέχει κάθε 20 λεπτά, ή όποτε πατήσεις «Refresh τώρα». Τα δεδομένα μένουν στο volume `vibe-flipper-data` (SQLite).

Ollama: αν τρέχει στον host, βάλε `OLLAMA_URL=http://host.docker.internal:11434`. Αν τρέχει σε container, βάλε και τα δύο containers στο ίδιο network και χρησιμοποίησε `http://ollama:11434`. Μοντέλο, URL και τρόπο matching τα αλλάζεις και από τις Ρυθμίσεις.

## Πώς δουλεύει

Κάθε run κάνει δύο πράγματα σε κάθε site:
1. **Αναζήτηση ανά προϊόν**, με τα `queries` του προϊόντος και τις νεότερες αγγελίες πρώτα.
2. **Category feeds** για ολόκληρες οικογένειες προϊόντων:

| Site | Feeds |
|---|---|
| Insomnia | Τελευταίες αγγελίες όλων των κατηγοριών, «Κάρτες γραφικών» και «Επεξεργαστές» (μόνο πωλήσεις) |
| Vendora | «Βιντεοπαιχνίδια & κονσόλες» και «Εξαρτήματα & αξεσουάρ υπολογιστών» |
| Vinted | «Κάρτες γραφικών» (3602) και «CPUs» (3599). Τα δεδομένα βγαίνουν από το Next.js payload της σελίδας, χωρίς headless browser |

**Αρχικό setup και deltas**:
- Στην πρώτη εκκίνηση με άδεια βάση, το Insomnia διαβάζεται **ολόκληρο**: όλες οι σελίδες και όλες οι κατηγορίες, περίπου 19.000 αγγελίες σε 45–60 λεπτά. Απενεργοποιείται με `INSOMNIA_FULL_INITIAL=false`. Τα Vendora και Vinted παίρνουν ένα βαθύτερο backfill.
- Μετά, κάθε run διαβάζει τα feeds (τα νεότερα πρώτα) **μέχρι τη σελίδα όπου όλες οι αγγελίες είναι ήδη γνωστές**. Αν δεν ανέβηκε τίποτα καινούργιο, αρκεί μία σελίδα. Αν ανέβηκαν πολλές, διαβάζονται όσες σελίδες χρειάζεται, έως 30.
- Οι αγγελίες αποθηκεύονται σελίδα-σελίδα. Αν ένα scrape διακοπεί, ό,τι μαζεύτηκε ως εκείνη τη στιγμή μένει στη βάση.
- Πλήρες scrape μπορείς να τρέξεις ξανά όποτε θέλεις από τις Ρυθμίσεις, ή με `python -m scripts.scrape_now --full --source insomnia`.

Οι GPU και οι CPU (162 μοντέλα) βρίσκονται μόνο μέσω των feeds. Έτσι δεν χρειάζονται 162 αναζητήσεις ανά site σε κάθε run. Ρυθμίζονται με τα `*_FEED_*` και `FEED_PAGES` στο `.env`.

**Matching** (Ρυθμίσεις → Τρόπος):
- `rules`: keywords, exclude, regex και εύρος τιμής ανά προϊόν. Το εύρος τιμής κόβει τα αξεσουάρ, τα παιχνίδια και τα PC που περιέχουν μια κάρτα γραφικών.
- `hybrid` (default): όταν οι κανόνες βρίσκουν ένα μόνο προϊόν, κρατιέται αυτό. Τις αμφίσημες αγγελίες, ή όσες μοιάζουν με κάποιο προϊόν, τις αποφασίζει το LLM. Το LLM βγάζει επίσης κατάσταση, bundle, «ζητώ» και «χαλασμένο».
- `llm`: όλα περνάνε από το LLM.

Κάθε αγγελία ρωτιέται στο LLM το πολύ μία φορά, γιατί η απάντηση αποθηκεύεται. Υπάρχει επίσης όριο κλήσεων ανά run (`LLM_MAX_CALLS_PER_RUN`). Οι χειροκίνητες αντιστοιχίσεις δεν αλλάζουν ποτέ αυτόματα.

**Τιμές**: η αγοραία τιμή είναι η διάμεση των αγγελιών των τελευταίων 30 ημερών, αφού αφαιρεθούν τα outliers (1.5×IQR). Δεν μετράνε οι αγγελίες «ζητώ», τα χαλασμένα, τα bundles και όσες εξαιρέσεις με το χέρι.

`κέρδος = διάμεση × (1 − προμήθεια%) − σταθερά έξοδα − κόστος αγοράς`

Στο Vinted το κόστος αγοράς περιλαμβάνει το buyer fee. Μια αγγελία παίρνει το badge **DEAL** όταν το περιθώριό της ξεπερνά τον στόχο του προϊόντος.

**Χώρα πωλητή**: μετράνε μόνο πωλητές από τις χώρες της ρύθμισης `ALLOWED_COUNTRIES` (default `GR`). Αλλάζει και από τις Ρυθμίσεις. Το Insomnia και το Vendora είναι μόνο Ελλάδα. Το vinted.gr δείχνει και αγγελίες από άλλες χώρες της ΕΕ, οπότε η χώρα βρίσκεται με έναν από τους παρακάτω τρόπους:
- Αν ο τίτλος είναι γραμμένος στα ελληνικά, η αγγελία θεωρείται Ελλάδα απευθείας.
- Αλλιώς, η χώρα διαβάζεται από το προφίλ του πωλητή μέσω του API χρηστών του Vinted. Η απάντηση αποθηκεύεται, ώστε κάθε πωλητής να ρωτιέται μία φορά, και υπάρχει όριο ερωτήσεων ανά run.

Οι αγγελίες εξωτερικού δεν μετράνε στα στατιστικά. Στις λίστες εμφανίζονται μόνο αν επιλέξεις «Και εξωτερικό».

**Αποθήκευση και καθάρισμα**: κάθε αγγελία αποθηκεύεται μία φορά, με κλειδί `(site, id)`. Σε κάθε run γράφονται μόνο οι νέες αγγελίες και οι αλλαγές τιμής, ενώ στις υπόλοιπες ενημερώνεται μόνο το «τελευταία φορά που τη είδαμε». Μία φορά την ημέρα σβήνονται οι αγγελίες χωρίς προϊόν ή από μη επιτρεπόμενες χώρες που δεν έχουμε ξαναδεί εδώ και `RETENTION_DAYS` ημέρες (default 30, 0 = για πάντα). Η ρύθμιση αλλάζει και από τις Ρυθμίσεις, όπου υπάρχει και κουμπί «Καθάρισμα τώρα». Οι αγγελίες με προϊόν, δηλαδή το ιστορικό τιμών, και οι χειροκίνητες αντιστοιχίσεις δεν σβήνονται ποτέ.

> Σημείωση: οι τιμές είναι *ζητούμενες* τιμές αγγελιών, όχι τιμές πώλησης.

**Παραλλαγές (specs)**: σε κάθε προϊόν ορίζεις ποια specs αλλάζουν την τιμή (RAM, αποθήκευση ή και τα δύο). Για παράδειγμα, το MacBook Air M2 έχει `[ram, storage]`, τα iPhone `[storage]`, και το RTX 3060 `[ram]`, όπου ram σημαίνει VRAM. Τα specs βγαίνουν από τον τίτλο και την περιγραφή (`16/512`, `8GB RAM 256GB SSD`, `1TB`), και από το LLM όταν χρησιμοποιείται. Κάθε αγγελία συγκρίνεται με τη διάμεση τιμή της **δικής της παραλλαγής**, αν αυτή έχει τουλάχιστον 3 δείγματα. Αν η παραλλαγή της είναι άγνωστη ή σπάνια, συγκρίνεται συντηρητικά με τη **φθηνότερη** παραλλαγή (εμφανίζεται ως `≥ 8GB / 256GB`).

## Προϊόντα

- `seed_products.yaml`: κονσόλες, iPhone, iPad, MacBook, Samsung, ήχος, drones κ.λπ., γραμμένα με το χέρι.
- `seed_hardware.yaml`: παράγεται από το `scripts/gen_hardware_seed.py` και περιέχει:
  - NVIDIA GTX 900 έως RTX 50, όλες οι εκδόσεις (Ti / Super / Ti Super).
  - AMD RX 6000 έως 9000 (XT / XTX / GRE).
  - Intel 10ης γενιάς έως 14ης, και Core Ultra 200S. Τα K/KF και τα απλά/F είναι ένα προϊόν το καθένα, γιατί έχουν σχεδόν ίδια τιμή.
  - Ryzen 3000 έως 9000. Τα X3D και τα G είναι ξεχωριστά προϊόντα.
  - SSD (128GB έως 4TB) και HDD (500GB έως 20TB) ανά χωρητικότητα, χωρίς διάκριση μάρκας. Τα 480/500/512GB μετράνε ως μία κατηγορία, το ίδιο και τα 960GB/1TB.
  - Μνήμες RAM ανά γενιά (DDR3/4/5) και συνολική χωρητικότητα κιτ, π.χ. το «2x16GB» μετράει ως 32GB.

  Για να αλλάξεις μοντέλα ή εύρη τιμών, επεξεργάσου το script και τρέξε `python -m scripts.gen_hardware_seed`, μετά `python -m scripts.sync_seed`.

Προϊόντα προσθέτεις από το UI (Προϊόντα → Νέο) ή από τη σελίδα «Χωρίς αντιστοίχιση» (**+ Προϊόν**). Με το πεδίο «Μόνο αν το spec της αγγελίας είναι» (ή `require:` στο YAML) ένα προϊόν ταιριάζει μόνο σε αγγελίες με συγκεκριμένη χωρητικότητα. Για παράδειγμα, το «SSD 1TB» έχει `require: {storage: 1024}`.

Τα keywords εφαρμόζονται στον *normalized* τίτλο: πεζά, χωρίς τόνους, και με διαχωρισμένα γράμματα και αριθμούς. Για παράδειγμα, το `ps5` γίνεται `ps 5`, το `RTX3070Ti` γίνεται `rtx 3070 ti` και το `M1` γίνεται `m 1` και το `5800X3D` γίνεται `5800 x 3 d`.

## Ανάπτυξη

```bash
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt pytest
.venv/Scripts/python -m pytest
.venv/Scripts/python -m uvicorn vibe_flipper.main:app --reload
```

Για άμεσο scrape: `python -m scripts.scrape_now`. Με `--backfill` διαβάζει περισσότερες σελίδες, κάτι χρήσιμο αφού προσθέσεις πολλά προϊόντα. Μην το τρέχεις ενώ τρέχει και το προγραμματισμένο scrape του container.

Αν αλλάξεις το `seed_products.yaml` αφού έχει στηθεί η βάση, πέρασε τις αλλαγές με το παρακάτω. Προσθέτει τα νέα προϊόντα και ενημερώνει τους κανόνες των υπαρχόντων με το ίδιο όνομα:

```bash
podman exec -it vibe-flipper python -m scripts.sync_seed
```

Οι νέες στήλες της βάσης προστίθενται αυτόματα στην εκκίνηση.

Σύγκριση των τρόπων matching πάνω στις χειροκίνητες αντιστοιχίσεις σου:

```bash
python -m scripts.eval_matching --ollama-url http://server:11434 --model qwen2.5:7b
# μέσα στο container:
podman exec -it vibe-flipper python -m scripts.eval_matching
```
